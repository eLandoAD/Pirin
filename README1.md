# SecureVault — Encrypted File Storage

> A web application for storing files with end-to-end encryption (E2EE). Files are encrypted **in the browser** before upload and decrypted **in the browser** after download. The server stores only ciphertext and can never read your files.

---

## Tech Stack

| Layer | Technology |
|-------|------------|
| Backend | Java 25 + Spring Boot 4 |
| Frontend | React 19 + Vite + Tailwind CSS |
| Database | MySQL |
| Encryption | Web Crypto API — AES-GCM 256, PBKDF2 |

---

## Quick Start

### Prerequisites
- Java 25
- Node.js >= 18
- MySQL on `localhost:3306`

### 1. Database

```sql
CREATE DATABASE secure_files;
```

Schema is auto-generated by Hibernate on first run.

### 2. Backend

```bash
cd Pirin
./gradlew bootRun
```

Configure `src/main/resources/application.properties`:

```properties
spring.datasource.url=jdbc:mysql://localhost:3306/secure_files
spring.datasource.username=root
spring.datasource.password=root

jwt.secret=your-secret-key-at-least-32-characters-long
jwt.expiration-ms=86400000

storage.path=uploads
app.frontend-url=http://localhost:5173

spring.mail.host=smtp.gmail.com
spring.mail.port=587
spring.mail.username=your-email@gmail.com
spring.mail.password=your-app-password
spring.mail.properties.mail.smtp.auth=true
spring.mail.properties.mail.smtp.starttls.enable=true
```

> **GitHub Codespaces:** set `app.frontend-url` to your Codespace frontend URL (e.g. `https://<name>-5173.app.github.dev`) and set port 8080 to **Public** in the Ports tab.

### 3. Frontend

```bash
cd frontend
npm install
npm run dev
```

App available at `http://localhost:5173`.

If running on Codespaces, update the proxy target in `vite.config.js`:

```js
proxy: {
  '/api': {
    target: 'https://<name>-8080.app.github.dev',
    changeOrigin: true,
  },
},
```

## Encryption — How It Works

Full design in [`SECURITY.md`](./SECURITY.md). Summary:

1. **Sign-up** — browser derives a **KEK** from the password via PBKDF2 (150 000 iterations, SHA-256)
2. A random 32-byte **DEK** is generated and encrypted with the KEK — only the encrypted DEK is stored on the server
3. **Upload** — browser: derives KEK → decrypts DEK → encrypts file with AES-GCM → sends ciphertext
4. **Download** — browser: derives KEK → decrypts DEK → decrypts file with AES-GCM
5. **Password change** — browser re-encrypts the DEK under the new KEK; no file re-encryption needed

The server never sees the password, the KEK, or the plaintext DEK.

## Features

### Core
- Sign up, email verification, login, logout (JWT)
- Password reset via email — DEK re-encrypted under new password
- E2EE file upload and download (AES-GCM 256)
- Upload progress feedback
- Drag-and-drop file upload
- Rename, delete, move files between folders
- Create, rename, delete folders (cascade) with nesting
- Drive-style folder picker for moving files
- Breadcrumb navigation
- Dark / Light mode

### Stretch goals implemented
- Drag-and-drop uploads

### Stretch goals — not implemented
- File previews (images, text) decrypted in-browser
- Search across file and folder names
- File sharing between users
- Multi-device key recovery
- Storage quota per user
